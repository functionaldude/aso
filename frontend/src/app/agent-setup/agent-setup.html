ASO and your coding agents share one public client ID. Their callbacks return the sign-in result to ASO’s server or the selected agent on your computer. Each client completes its own login; your provider’s browser session may make signing in quicker.

Your administrator registers each exact callback once and enables refresh-token access. Configuration reflects this installation’s settings; it does not verify the provider’s registration. Codex’s local callback_port must match callback_url. Claude Code uses port 8767; Cursor desktop uses port 8787.

All setup examples request offline_access so the client can refresh its login. If you previously connected without it, update your configuration and authenticate again. Your provider must also allow that scope; Authentik needs its offline_access scope mapping enabled.

Troubleshooting
  • Cannot connect: check the MCP URL and that ASO is running. For local development, use the backend URL rather than Angular’s port 4200.
  • Login or redirect fails: ask your administrator to check the registered callback for the selected client and its listener port. If the port is already in use, close the other login attempt and retry.
  • Wrong account or expired login: use your client’s authentication controls and the provider’s browser session to sign in again and check identity.
  • ASO or search is unavailable: tell the agent to continue local work and report the limitation.
  • A write times out: retain the original request or event ID, check current state, and follow the error before retrying.
